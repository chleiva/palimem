# S-11 — Attributed reports: quarantine, confirmation and nesting

Status: proposed · Gate: G0 · Lane: A · Related: S-01, S-03, S-09

## Context

**Deposited code.** None. `Observation` has no origin class and no notion of attribution; every `assert` is a first-order claim. Setting 2/3 pipelines use no `belief_of`. So the whole attribution machinery (`attributed` origin, `belief_of(holder, P)`, "establishes the attribution only") is new and **has no oracle**.

**Design v0.3.** `attributed` reports are admissible as evidence for the attribution only, corroborated by any number of origin groups they establish `belief_of(holder, P)` and never `P`; deriving `P` needs a declared rule with the holder's class as a premise. Not specified: (a) whether a quarantined source's `attributed` report can be confirmed, (b) whether `belief_of(h1, belief_of(h2, P))` is allowed.

## Options

A. **Uniform rules, depth ≤ 1 (recommended).** Quarantine and confirmation apply to an attributed report exactly as to any report, with "equivalent proposition" taken over the whole `belief_of(holder, P)` term (after canonicalising `holder` through entity resolution). Nested attribution is a schema error in v1.
B. **Bounded nesting** (depth ≤ 2). Enables "Bob thinks Alice believes P", with a clear need to define candidate ids and rules.
C. **Arbitrary nesting.** Unbounded term size and no use case.

## Recommendation

**A.** Attributions belong to the *source's* admissibility, not the holder's: a report from a quarantined source that Alice believes P is quarantined until a report from an independent origin group says the same. Depth ≤ 1 keeps `Candidate.id = hash(key, form, canonical content)` simple. Derivation of `P` from an attribution stays a declared rule; the rule's premise is `belief_of(holder, P)` with `holder.class` as a condition, and the derived belief pins the attribution reports like any other derivation.

## Effect on `revise-stream-v1` and G1

None. The profile admits no attributed reports.

## Open questions

1. Are `belief_of` candidates ever eligible for `decision = commit`? Recommend yes (a policy may commit to "Alice believes P"), and never imply `P`.
2. Is the holder an entity key subject to the same schema/class rules (e.g., a `person` class)? Recommend yes, so `find()` and merges apply.
