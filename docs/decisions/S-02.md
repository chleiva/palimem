# S-02 — Authority: same origin vs same source, and what the paper actually does

Status: amended (2026-10-04) · Gate: G0 (blocks G1) · Lane: A · Related: S-01, S-03, S-07

## Context

**Design v0.3.** `correct` / `withdraw` / `dispute` need authority; default is "the target's own source". A failed check records the report as `allege`, which "has no effect on admissibility". `withdraw` targets a report id.

**Deposited code (checked).**

1. **A-SELF is origin-based.** `Stream.self_corrections` withdraws the target when `sources[o.source].origin == sources[tgt.source].origin`. Two different sources sharing an origin (`press`/`wire`, `wiki`/`mirror` in `generator.py`) qualify; the design's same-*source* default would reject them. The proposal's S-2 description is correct.
2. **A-SELF is wider than the proposal says.** `self_corrections` iterates *all* observations with `t_rep ≤ τ`, not the admitted ones. A correction from a `blocked` source, or one that is itself later retracted, still withdraws its target. (Blocked sources are never generated, so only retracted corrections can occur in frozen data: the generator retracts any `assert`, corrections included, with probability `p_retract_obs`.) Whether the paper's behaviour for a retracted correction (target stays withdrawn) or the intuitive one (target is restored) is intended is **not stated** in SEMANTICS §4. This can produce a G1 disagreement; it must be tested by the differential harness (T-E1) before the profile is frozen.
3. **`retract` has no authority check at all.** `Stream.admitted` applies every `retract` observation. The generator issues two kinds: observation retracts from the *target's own source*, and **wholesale source retracts issued by `registry` (a trusted source in another origin) against a non-trusted source** (`generator.py`, `p_retract_source = 0.35`, so roughly a third of streams). The design has no source-level withdrawal (`withdraw.target` is a report id) and its default authority would reject the registry's retract. **This is a G1 blocker.**
4. **Cross-origin corrections are not withdrawals and are not ignorable.** A correction from another origin (`p_cross_correct`, including `low`-class correctors) is an admitted assert with `op_cue = correction`. Under A-CORR it forces the target to `ERR` in every interpretation where the correction is TRUE, so it turns `erroneous(o)` into `possible` and can resolve disputes. The design's rule "failed authority ⇒ `allege` ⇒ no effect" would erase this.
5. **There is no explicit `dispute` operation in the paper.** Disputes are structural (SEMANTICS §5: differing values on one key, or opposite polarity). The design's `dispute` cue is new.

## Options

A. **Strict default, compat profile overrides (recommended).** Product default: `correct`/`withdraw` authority = same `origin_group` as the target's source (not same source). Add `withdraw(target: report | source)`. Split the failure behaviour of `correct`: an unauthorised `correct` is *not* an `allege`; the report remains an ordinary admissible `assert` (if its source is admitted) carrying `corrects: <target>` as an A-CORR hint. `allege` is reserved for `withdraw` and `dispute` that fail authority. Profile `revise-stream-v1` sets `authority.withdraw = any` (the paper's behaviour) and `correct.withdraw_effect = same_origin_group`.
B. **Make the paper's behaviour the product default** (retract unrestricted). Simple, but it lets any admitted source erase any report; it contradicts the design's accountability goal.
C. **Pluggable authority only.** Defer; ship no default. Rejected: undefined default breaks the independent "unauthorised withdrawal" fixture.

## Recommendation

**A.** Also decide the retracted-correction quirk explicitly: product semantics should require the correction to be admitted *and not withdrawn* at the time it acts (a withdrawn correction restores its target). If the differential run shows frozen sets depend on the paper's behaviour, add a profile flag `a_self_requires_live_correction: false` and record a dated note in the pre-registration addendum.

### Amendment (author decision, 2026-10-04): agents have no authority over external evidence

The default same-origin-group rule is the *source-side* default and does not apply to agent principals. For an agent acting through the tool API:

- it may withdraw or correct **only** reports whose `actor` is that agent principal **and** whose origin is agent-class (`agent_hypothesis`, `agent_statement`, `plan`), from any earlier session; identity is bound by the host API, never supplied by the LLM;
- it may **never** withdraw or correct an `external_observation`; such an attempt is recorded as `allege` (no effect);
- it may `dispute` only where the host has granted that agent principal a `dispute` rule for the key scope; otherwise the write lands as `allege`;
- a granted dispute does **not** quarantine the disputed source (deferred; default no).

This sits *beside* A: it does not change the compat profile (the frozen sets contain no agent principals), but it constrains what "any grant" can mean (see S-07 invariant). Detail: `docs/API_TRUST_BOUNDARY.md` R6.

## Effect on `revise-stream-v1` and G1

Required for 0 disagreements: unrestricted `withdraw` incl. source-level, origin-group A-SELF, cross-origin correction retained as admissible assert with A-CORR hint. Without these, roughly 35% of Setting 1 streams (source retracts) and every cross-origin-correction stream disagree.

## Open questions

1. Do you want the retracted-correction behaviour decided from the harness result or by principle first?
2. Should an unauthorised `correct` still be able to *resolve a dispute* by itself? In the paper it never does (SEMANTICS §11.1, birthdate stream); keep that.
3. **Kernel semantics of an authorised `dispute` are undefined in design v0.3** (the paper has no explicit dispute operation, only structural disputes). Recommend: an authorised dispute plays the role of the A-ERR *competitor* for its target, so the target may be labelled ERR and the segment becomes `unresolved` with the target's value and the empty candidate as alternatives; it never withdraws. Fixture `tb-18` assumes this.
4. Source-level withdrawal: should it be limited to a source's *future* reports, past reports, or both? Paper: all reports of that source reported at or before the retract time and after (it removes the source from the assumption set from `t_rep` onward, including earlier-reported observations).

### Decision (author, 2026-10-04): amended
- **Compat profile `revise-stream-v1`: authority is origin-based**, because that is what reproduces the deposited numbers and the differential CI is the point of the profile.
- **Product default: authority belongs to the source (the principal)** who authored the target, as in design v0.3. `origin_group` is used for **corroboration counting only, never for authority**: a shared origin is exactly what an attacker can imitate. This reverses recommendation A's product default.
- **Required fixture `compat-authority-coincide`** asserting that on the frozen sets origin-based and source-based authority give identical A-SELF results, so the profile cannot silently drift.
  - *Verification note (2026-10-04, Claude):* the premise "every report has one source and that source is its origin" is **not** literally true: in all 500 frozen Setting 1 streams several sources share an origin (the correlated mirrors). The conclusion nevertheless holds for A-SELF there: of 5,505 correction reports, **0** are made by a different source of the same origin as their target. The fixture must therefore assert *that* property, not source == origin. Settings 2 and 3 are not covered by the harness and are unverified.
- A-SU (P0cSU) stays origin-based: it is a *semantic* supersession rule, not an authority rule.
- The retracted-correction quirk: product semantics require the correction to be live; the compat profile flag `a_self_requires_live_correction: false` is added only if the differential run shows the frozen sets depend on the paper's behaviour (dated note in the pre-registration addendum).
- The agent amendment above stands unchanged.

### Implementation and measurement note (T-D1 / T-D2, 2026-10-05): decision unchanged

Implemented in `palimem.admission` and verified on the 500 frozen Setting 1 streams by `tests/test_compat_authority_coincide.py` (the required `compat-authority-coincide` fixture):

* 5,505 corrections, **0** made by a different source of the same origin as their target; origin-based and source-based authority therefore give **identical** A-SELF results on every stream.
* The SDK's compat admission reproduces the study's `Stream.self_corrections` on all 500 streams, and the study's `Stream.admitted` on the 314 streams that have no source-level retract.
* **The retracted-correction flag is required, not optional.** 387 of the 5,505 corrections are themselves retracted. With `acting_reports_must_be_live = true` (the product default) the admitted set differs from the paper's on **84 of those 314 streams**; the compat profile therefore sets `acting_reports_must_be_live = false` (`a_self_requires_live_correction: false`). Per the record, this needs a dated note in the pre-registration addendum.
* **Open gap.** The 186 streams with source-level retracts (the registry retracting a source, `retract(target=<source id>)`) cannot be expressed as a `withdraw` Report, whose target is a report id. They are excluded from the admitted-set comparison. The compat adapter (T-E3) needs a request-level discriminator (for example a `scope: report | source` marker on the withdraw), which is a contract question for the author.
* Settings 2 and 3 remain unverified (task T-J5).
