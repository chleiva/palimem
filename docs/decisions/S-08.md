# S-08 — Inertia: paper A4 versus a per-attribute `inertia` flag

Status: amended (2026-10-04) · Gate: G0 (blocks G1) · Lane: A · Related: S-04, S-09

## Context

**Design v0.3.** `Attr.inertia: bool` — "a changeable value holds for valid_at queries until changed"; "inertia applied only to keys declared `inertia: true` and interval ends left open when no report closes them".

**Deposited code (`oracle_v1._sweep`, `timeline.Segment`).** Law of inertia (A4) is **universal**, and it is *not* tied to `changeable`:

- Single-valued: the last run gets `end_lo = end_hi = INF` (persists forever), for changeable and non-changeable keys alike.
- Non-changeable keys: all TRUE values must be equal (A-STABLE), one run, persists forever.
- Multi-valued changeable: each run followed by another run chooses CONT (persists) or ENDED (ends in the unknown gap before the next run's anchor); multi non-changeable: `slots = []`, everything CONT.
- `changeable` therefore controls **consistency** (whether differing values are a change or a contradiction) and the CONT/ENDED branching, **not persistence**.
- Before the first anchor a value covers nothing (`start_lo == start` for the first run); there is no backward persistence.
- Between a run and the next run's anchor the change point is unknown (`Segment.covers` returns `None` in the gap) and `asof` inside a gap is `unresolved {v_prev, v_next}` by design (SEMANTICS §11.3).

So the proposal's reading is right that A4 is universal, but the real issue is wider: the design's flag has no defined meaning for `inertia: false`, and for stable classes inertia is forced.

## Options

A. **`inertia: forever | ttl(duration) | none`**, default `forever` (= A4). Stable classes force `forever`. `none` means the value is justified at the report's anchor only; `ttl` bounds persistence (end becomes a gap at anchor+ttl, treated like an unknown change point).
B. Boolean as designed, with `false` meaning "no persistence beyond the anchor". Loses `ttl`, which most real "current location/status" attributes want.
C. Keep A4 universal; no flag. Simplest and fully oracle-equivalent, but unrealistic for volatile facts (e.g., "currently in a meeting").

## Recommendation

**A.** Define `none` and `ttl` as *semantic* options: they are part of the stored semantic/schema version. Unknown change point semantics reuse the existing gap mechanism, so the kernel gains no new machinery.

## Effect on `revise-stream-v1` and G1

The profile sets `inertia: forever` on every attribute, which reproduces `_sweep` exactly. G1 unaffected.

## Fixtures implied

- `fx-S08-forever-persists-to-infinity` (profile and product).
- `fx-S08-no-backward-persistence`: query before first anchor → no candidate.
- `fx-S08-gap-asof-unresolved`: query inside the change gap → unresolved {v_prev, v_next}.
- `fx-S08-ttl-expires-into-gap`: query after `anchor + ttl` → unresolved/unknown per the gap rule.
- `fx-S08-none-point-valued`.
- `fx-S08-stable-forced-forever`: `inertia: none` on a stable attribute is a schema error.

## Open questions

1. Does `ttl` end in an *unknown* change point (gap) or a definite end? Recommend gap, consistent with the paper's "change point unknown" stance.
2. Should the default be `forever` for `single_changeable` in the product, or `none` (more conservative)? Paper says `forever`; recommend keeping it, and documenting the cost.

### Decision (author, 2026-10-04): amended
**Per-attribute, using the `Attr.inertia` boolean of design v0.3.** The compat profile sets it to match the paper: single-valued changeable keys hold for `at` queries until changed; stable keys and sets do not. The `forever | ttl | none` enum of recommendation A is **not accepted** (it would change `Attr`); revisit only by an explicit author line before G0 freezes.

### Implementation note (T-D, 2026-10-05): aligned to the types, decision unchanged

`Attr.inertia` is a boolean in `palimem.types` and in every trust-boundary fixture (they used the string `"forever"` before; all 60 occurrences are now `true`). The `ttl` / `none` options and the fixtures `fx-S08-ttl-expires-into-gap`, `fx-S08-none-point-valued` and `fx-S08-stable-forced-forever` listed above belong to the **rejected** enum and are not built; `fx-S08-forever-persists-to-infinity`, `fx-S08-no-backward-persistence` and `fx-S08-gap-asof-unresolved` still apply with `inertia: true`.

One nuance for the author, not a change of decision: the deposited `_sweep` applies persistence to *every* attribute (a non-changeable key's value runs to +inf by definition; a multi-valued run to +inf if CONT). The boolean therefore only reproduces the paper if the compat profile sets `inertia: true` on **every** attribute it declares, not only on the single-valued changeable ones. The decision text ("stable keys and sets don't") would, read literally, differ from `_sweep`; the kernel lane should settle it with the differential run.
