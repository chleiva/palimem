# S-05 — The belief axis: wall-clock versus log sequence

Status: proposed · Gate: G0 · Lane: A · Related: S-09

## Context

**Design v0.3.** `recorded_at` (wall-clock timestamp set by the log) is the belief axis; `belief_as_of` selects "the belief version current at that log time".

**Deposited code.** Belief time τ is an **integer** equal to the report time `t_rep`; the oracle at τ uses exactly the observations with `t_rep ≤ τ`. Findings beyond the proposal's S-5:

- **Ties are real.** The generator's `_delay()` can return 0 and observations are sorted by `(t, id)`, so several observations share one τ. Semantics treat them as a *batch*: all become visible at once. `core.py` stores one `KeyVersion` per recompute with `tau = o.t_rep`; `_version_index` picks the **last** version with `v.tau ≤ tau`.
- **Valid "now" equals belief time.** `gold_for` uses `t = q.t if q.t is not None else tau` for `current`/`downstream`. In the benchmark, valid time and belief time share one integer scale and "now" is τ.
- The `belief_asof` slot passes `q.tau_prime` and re-runs everything at τ′ (inclusive `≤`).

Wall-clock timestamps give no total order across restarts, tie handling or clock skew, and cannot reproduce the batch semantics.

## Options

A. Wall-clock `recorded_at` as designed.
B. **Log sequence number (LSN) as the belief axis (recommended)**; `recorded_at` is a monotone-clamped lookup index. `belief_as_of` accepts an LSN, or a timestamp resolved to "the last LSN with `recorded_at ≤ t`".
C. Hybrid logical clock. More machinery than a single-writer store needs.

## Recommendation

**B.** Define precisely:
- LSN is assigned inside the append transaction, strictly increasing, gap-free per store.
- `recorded_at` is `max(wall_clock, previous.recorded_at)` so it never goes backwards.
- A belief version is identified by the LSN of the append that created it. `belief_as_of(lsn)` is inclusive.
- Compat profile: report time τ maps to `LSN(τ) = last LSN among reports with t_rep ≤ τ` (ties = batch, matches the oracle). Default `valid_at` under the profile is τ's day, not wall-clock now.

## Effect on `revise-stream-v1` and G1

The adapter implements the τ→LSN map and the default-valid-time rule. Without the second rule every `current` query is evaluated at the wrong valid time. G1-relevant.

## Fixtures implied

- `fx-S05-tie-batch`: two reports share τ; a query at τ sees both, a query at τ−1 sees neither.
- `fx-S05-clock-goes-backwards`: wall clock steps back by an hour; LSN order and `belief_as_of` unchanged.
- `fx-S05-restart-ordering`: LSNs continue after restart; no reuse.
- `fx-S05-belief-as-of-boundary-inclusive`.
- `fx-S05-timestamp-resolves-to-lsn`: timestamp between two appends resolves to the earlier one.

## Open questions

1. Is a per-store LSN enough for the planned MongoDB backend (a second implementation)? A replica-set backend would need an equivalent monotone counter; make "monotone gap-free sequence" a backend-interface requirement. (Separately, `verify_log(from, to)` is an *optional-capability* backend operation for the log hash chain, a storage-layer property that is not part of the `Report` contract; see S-13 and `docs/VERSIONING.md` §6.)
2. Should `Query.belief_as_of` accept both forms on the wire? Recommend yes, with LSN canonical in responses.
