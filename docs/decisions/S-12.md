# S-12 — `explain` depth and the provenance contract

Status: accepted* (2026-10-04) · Gate: G0 (blocks G1) · Lane: A · Related: T-B4, S-06

## Context

**Design v0.3.** "`explain(key, valid_at, mode: all | one)` returns the applicable supports two levels deep", while the retraction requirement is "two or more steps downstream" and the provenance contract is "all subset-minimal environments applicable in the answered segment".

**Deposited code.**

- Oracle provenance is a **flat set of observation ids**, computed by `gold.support_ids`: for an observed key, the admitted assertions whose value is a candidate; for a derived key, every admitted assertion asserting a `(key, value)` binding used on *any* derivation path that yields a candidate, with sub-traces folded in (`timeline._eval_rule`: "a derived body literal: fold its own paths in"). That is **full depth**, not two levels.
- Rule recursion is capped at depth 8 (`candidates_at`, `relevant_keys` raise `RecursionError` beyond it).
- `core.py` `_path_prov` reproduces the same flat set. `BeliefStore._prov_ids` falls back to *all* admitted ids when status is `unresolved|possible|unknown` (and for established, ids whose value is asserted).
- The released domains' longest chain is `employer → work_city → local_tax_city` (README): two *derived* levels over observed keys. "Two levels deep" is probably a description of that generator, not a contract.

The oracle has no concept of subset-minimal *environments*, so the "2–5% provenance gap" is a gap between the SDK's richer contract and the oracle's flat sets: they will always differ unless the adapter defines how environments flatten.

## Options

A. **Depth is a parameter; default = full closure bounded by the explanation budget (recommended).** `explain(depth: int | None = None)`; the schema forbids rule chains deeper than 8 (matching the oracle). The adapter flattens subset-minimal environments to the union of report ids on applicable minimal environments.
B. Fix depth at 2 as stated. Breaks full-chain explanations and G1 provenance parity for any deeper schema.
C. Unbounded without budget. Output can be exponential (R4.1).

## Recommendation

**A.** Define provenance precisely as (i) all subset-minimal environments applicable in the answered segment; (ii) for derived keys, environments over **base** reports (derivation pins are explanatory, not evidence); (iii) the adapter projection `flatten(environments) = ⋃ ids` must equal oracle provenance exactly, and that equality, not "within 2–5%", is the G1 provenance criterion. Where the SDK and oracle genuinely differ (e.g., `unresolved` fallback to all admitted ids), the *profile* reproduces the oracle's rule and the product keeps the principled one.

## Effect on `revise-stream-v1` and G1

Profile provenance = oracle's flat set, including the unresolved/unknown fallback. G1's "provenance identical" is achievable only through this explicit projection.

## Fixtures implied

- `fx-S12-depth-3-derivation-withdraw-at-leaf`: withdrawing the leaf report removes the conclusion; `explain(depth=None)` lists the leaf.
- `fx-S12-explain-depth-1-truncated-marker`: `explanation: truncated`; kernel_status/decision unchanged.
- `fx-S12-rule-depth-9-refused-at-load`.
- `fx-S12-flatten-equals-oracle-flat-set` (differential).
- `fx-S12-unresolved-provenance-fallback-profile-only`.

## Open questions

1. Is `explain(mode: one)` canonical choice deterministic across versions (e.g., lexicographically least minimal environment by report id)? Recommend yes, documented, since agents may cache it.
2. Is the depth-8 limit a hard product limit or a schema-level default? Recommend a default of 8 with refusal beyond it, until T-I1 says otherwise.
