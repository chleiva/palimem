# S-09 — Partial-date precision, `valid_to`, and negative evidence are outside the validated kernel

Status: proposed · Gate: G0 · Lane: A · Related: S-05, S-08, S-11

## Context

**Design v0.3.** `valid_from`/`valid_to` timestamps with `precision: day | month | year`; propositions `not_value`, `not_member`, `enumeration([])`.

**Deposited code.** Valid time is an **integer number of days**. Reading `model.py`: only the cues `none`, `since`, `at` are implemented; `Observation.anchor` raises `NotImplementedError` for `until` and `interval`, and `Stream.admitted` raises `NotImplementedError("negative polarity deferred to Phase 1")`. SEMANTICS §3, §5 and §7 describe `until`, `interval` and negative polarity (A3) as if specified, but the model docstring says they are deferred, no generator path emits them, and `build_setting3.py` contains none. So:

1. **Partial-date precision**, **`valid_to`** and **negative polarity (`not_value`, `not_member`)** have *no oracle implementation and no frozen query*. G1 cannot validate them.
2. Everything the design adds on those three axes rests on the independent fixtures alone.

The proposal presented only the first of these (as S-9); the second and third are the same gap and bigger in effect (negative evidence drives the open-world ladder).

## Options

A. **Staged support (recommended).** 0.1: `precision = day` only, no `valid_to`, no negative propositions (schema rejects them). 0.2+: add them with a *new reference implementation of the oracle extension*, written independently of the SDK kernel, and diffed by the fuzzer, plus the independent fixtures.
B. Implement all in the SDK kernel directly and rely on the independent suite. Fast; no second implementation to diff against.
C. Extend `oracle_v1` first (in `~/palimpsest`) and re-run the study. Cleanest scientifically, but it reopens a deposited, DOI-cited artefact and the pre-registration.

## Recommendation

**A**, with the extended oracle living in the SDK repo's harness (`harness/oracle_ext`) as a *separate* brute-force implementation. Define partial dates as **interval-valued anchors**: a report with precision `month` anchored in March 2020 has anchor in `[2020-03-01, 2020-03-31]`; the sweep treats the unknown exact day like the existing unknown-change-point gap. Day precision reduces exactly to the paper's integer semantics. `valid_to` closes a run the way `until`/`interval` would in SEMANTICS §7, with the same A2 caveat for missing starts. Negative evidence follows A3 (a TRUE negative ends the value's interval at its anchor and contradicts a later positive).

## Effect on `revise-stream-v1` and G1

None under A: the profile uses day precision and no negative evidence. Under B or C G1 is untouched but the *product* semantics for these features is unvalidated until the extended oracle agrees.

## Fixtures implied

- `fx-S09-day-precision-equals-integer-semantics` (parity with oracle_v1).
- `fx-S09-month-precision-unresolved-inside-month`.
- `fx-S09-year-vs-day-conflict`.
- `fx-S09-valid-to-closes-run`.
- `fx-S09-not-value-distinct-candidates` (independent suite: "not Acme" and "not Globex" stay distinct).
- `fx-S09-negative-then-positive-later`: A3 ordering.

## Open questions

1. Is negative evidence in scope for 0.1? Recommend no: it widens the semantics most and has no oracle.
2. Timezones: valid time is day-granular and timezone-naive in the paper. Recommend UTC days and an explicit statement that sub-day precision is out of v1.
