# S-06 — Behaviour above the environment cap

Status: accepted* (2026-10-04) · Gate: G0 · Lane: A · Related: T-B6, T-B7, T-I1

## Context

**Design v0.3.** Hard cap `n ≤ 12` reports per key, "with overflow to a per-key replay path". Write cost is "2^n".

**Deposited code (checked).**

- The replay oracle *is* exponential: `oracle_v1._key_interps` loops `for mask in range(1 << n)`. Overflow to replay changes nothing asymptotically.
- It is worse than 2^n for multi-valued keys: for each admissible label mask, `_sweep` takes `product(["CONT","ENDED"], repeat=len(slots))`, and `observed_candidates` adds `2^|ambiguous|` per query. The right budget unit is *enumerated interpretations*, not reports.
- `n` is the number of **admitted** reports on the key (`admitted_by_key`), so withdrawn reports stop counting.
- **The validated envelope is smaller than the cap.** `GenConfig.max_obs_per_key = 7` ("bounds per-key enumeration (2^7 subsets)"). No frozen query exercises n > 7. CI runs `oracle_validation.py --max-obs 12` on a small sample, and the script has an `n_skipped_large` counter. The 40,030-query agreement therefore does not support a default of 12.
- `core.py` `_interp_fn` takes a `product` across keys too; only the per-key route is exact (and only under the static closure condition, which exists as `body_closures_disjoint` in `scripts/oracle_validation.py` and is not enforced at load).

## Options

A. **`ResourceLimited(environment_budget)` for the key (recommended).** Above the budget the key has no `Resolved` answer; `last_complete` may be served, labelled.
B. Truncate to the latest `n` reports. Changes the semantics silently; rejected.
C. Sound over-approximation: list every value ever admitted as `unresolved` alternatives, marked `explanation: approximate`. Cheap, but alternatives may not be justified and status disagrees with the oracle.

## Recommendation

**A**, with two preconditions that make it rarely trigger: (1) **equivalence collapsing** before enumeration (same key, equivalent proposition, same `origin_group`, same cue, no distinguishing valid-time), (2) the budget is stated in enumerated interpretations with `n` as a proxy. Default budget: the count that corresponds to n = 7 (validated) until the harness validates more; raise it only with oracle agreement evidence at the higher n (T-E4 fuzzer). This record does **not** prejudge T-I1: if the R4.1 spike finds a polynomial class, the budget semantics stay the same and the threshold moves.

## Effect on `revise-stream-v1` and G1

None: the generator never exceeds 7. The profile sets the budget above 7 so the frozen sets are never limited.

## Fixtures implied

- `fx-S06-over-budget-resource-limited`: 13 distinct-origin conflicting reports → `ResourceLimited`, no `kernel_status`.
- `fx-S06-collapse-duplicates`: 30 equivalent reports from one origin group → same answer as the single-report reference.
- `fx-S06-withdrawal-brings-key-under-budget`: withdrawing reports restores `Resolved`.
- `fx-S06-multi-valued-budget-in-interpretations`: a multi-valued key with n=6 but many runs exceeds a small budget.
- `fx-S06-last-complete-labelled`.

## Open questions

1. Should the budget be per key, per schema attribute (declared), or global? Recommend per attribute with a global default.
2. May a user raise the cap at their own risk? Recommend yes, with the cap recorded in the semantic configuration stored with each belief version.

### Decision (author, 2026-10-04): accepted with one qualification
Accepted subject to the R4.1 result and the kernel decision in T-B10: the **enumeration kernel under the resource budget is the production kernel through G1** and remains the audit oracle permanently. Equivalence collapsing is **not** a kernel precondition (R4.1: it changes answers at historical valid times in 41% of instances); use it only as a current-time optimisation. Adding `environment_budget` to the `ResourceLimited.reason` enum changes the Answer contract and needs an explicit author line before G0 freezes. Open: default environment budget (design: 12; validated envelope: 7).
