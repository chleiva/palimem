# S-10 — Defeasible-rule exceptions under open-world semantics

Status: proposed · Gate: G0 · Lane: A · Related: S-04, T-B9

## Context

**Deposited code (`timeline._eval_rule`).** A rule's `exceptions` are evaluated at the leaf of each derivation: `candidates_at(...)` on the exception key gives candidate sets; the rule is blocked in a world only if `xv in S`. For an exception key with no evidence, the candidate set is `{∅}`, `xv ∉ ∅`, so **the rule fires**: absence of the exception is treated as *the exception does not hold* (negation as failure, i.e. a closed-world assumption on exception keys). An *unresolved* exception (several candidates) already yields several worlds, hence an `unresolved` derived answer. Other facts:

- Body literals with no evidence give `∅` and that world simply yields no head value, so unknown bodies produce `unknown`, not false. Only **exceptions** are closed-world.
- Rule literals hard-code `ctx = ""` (`(x, la, "")`); contexts are not supported in rules.
- The "each base key reached at most once per derivation path" condition is assumed in the comment of `candidates_at` ("holds for the declared rule sets"). A static check `body_closures_disjoint` exists only in `scripts/oracle_validation.py`, not at load.

**Design v0.3.** Open world by default: absence is `unknown`; yet derived rules with exceptions are not mentioned beyond the static check. The proposal flags this as S-10 correctly; it understates one thing: the paper is *already* open-world for bodies and closed-world for exceptions.

## Options

A. **Exceptions follow the exception attribute's completeness (recommended).** If the exception key is closed (`declared(scope)`, or `by_enumeration` with an enumeration covering the interval), absence ⇒ exception false ⇒ rule fires (paper behaviour). If it is `open` and has no evidence, the exception is *unknown*: two worlds (fires / blocked) ⇒ the derived belief is `unresolved` with the candidate and the empty candidate.
B. Keep NAF unconditionally (paper). Preserves G1 trivially; but makes a derived belief `established` on the strength of an unverified absence, contradicting the open-world principle.
C. Require explicit negative evidence for every exception before any rule fires. Too conservative: nothing derives.

## Recommendation

**A.** It is principled (NAF *is* the closed-world assumption restricted to the exception key) and needs no new rule syntax. Surface it in `inquiry`: the missing key is exactly the exception key, so `decision = ask` can name it. Make the "reachable once per path" check a **load-time refusal** with the {A, B, ∅} counter-example as the regression test (T-B5), and give rules a context-carrying form or document `ctx = ""` as a v1 limitation.

## Effect on `revise-stream-v1` and G1

The profile declares every frozen key `completeness: declared(all)` for exceptions, so exceptions are closed and rules behave exactly as the oracle. No G1 risk. (Reminder from S-04: `declared(all)` must be applied per key class, not blanket.)

## Open questions

1. Do you want a per-rule override (`exception_mode: naf`) for users who deliberately want defaults-unless-known-blocked? Recommend yes, explicit and recorded in the schema version.
2. Does `by_enumeration` completeness on the exception key cover the rule's valid-time interval only or all time? Recommend: only the interval of the covering enumeration.
