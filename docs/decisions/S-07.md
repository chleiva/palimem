# S-07 — Principal and authority model

Status: accepted* (2026-10-04) · Gate: G0 · Lane: A · Related: S-02, API_TRUST_BOUNDARY.md

## Context

**Design v0.3.** `Report.actor: principal`, `Attr.authority: {correct: [principal rule], withdraw: [...], dispute: [...]}`, and "the target must lie in the actor's key scope". None of `principal`, "principal rule" or "key scope" is defined.

**Deposited code.** There is no principal concept. The only identities are `Observation.source` and `Source.origin`; authority is implicit: A-SELF = same origin, `retract` = unrestricted (S-02). So the SDK model is designed from scratch and has **no oracle to test it against** except through the profile's permissive setting.

## Options

A. **Minimal grant table (recommended).** A principal is an opaque string id assigned by the host (`user:alice`, `agent:planner`, `connector:registry`), carrying an optional `origin_group`. Authority is a declarative list of rules; first match wins; default is deny except the S-02 default.
   ```
   AuthorityRule { who: principal | origin_group | "*", may: [correct|withdraw|dispute],
                   on: {attr pattern, entity pattern}, targets: report | source | any }
   ```
   `Attr.authority` supplies per-attribute rules; the store has a global rules list below it.
B. **Pluggable callback** `authorize(actor, cue, target, key) -> bool`. Flexible, not auditable or versionable.
C. **Roles (RBAC).** More structure than a single-process v1 needs.

## Recommendation

**A**, versioned as part of the admission version (an authority change is an admission change). Key scope = the `{attr, entity}` patterns in a rule, matched with glob on attribute names and exact-or-glob on canonical entity ids. A B-style callback may be added later *under* A as a rule kind, never instead of it.

### Amendment (author decision, 2026-10-04): principal kinds and the agent invariant

- A principal has a **kind**: `agent | user | connector | system`, carried in its id prefix (`agent:planner`, `user:alice`, `connector:registry`, `system:admin`) and fixed by the host at registration. The kind is not changeable by the principal.
- **Built-in default rule for agent principals:** may `withdraw` and `correct` reports where `target.actor == self` and `target.origin ∈ {agent_hypothesis, agent_statement, plan}`. Identity-based, so it works across sessions; it is not a session scope.
- **Hard invariant, checked when rules are loaded or changed:** no `AuthorityRule` may grant a principal of kind `agent` the power `withdraw` or `correct` over an `external_observation` (nor a `targets: any`/`source` withdraw). Such a rule is refused with an error, and an admission-version bump cannot override it. Humans and systems act through the host API.
- `dispute` for an agent principal exists **only** by explicit grant scoped to `{attr, entity}` patterns; otherwise `allege`. A dispute never quarantines the disputed source (deferred; default no).
- Resolves open question 1 below: no implicit rank for end users over agents; the user's own corrections are host-API calls with the user as actor.

## Effect on `revise-stream-v1` and G1

The profile installs `[{who:"*", may:[withdraw], targets:any}, {who: same_origin_group, may:[correct]}]`. All frozen-set behaviour then follows the paper (S-02). No G1 risk beyond S-02.
