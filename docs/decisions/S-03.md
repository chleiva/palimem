# S-03 — Paper `blocked` versus design `quarantined`

Status: accepted (2026-10-04) · Gate: G0 · Lane: A · Related: S-01, S-02, S-11

## Context

**Paper / code.** Source class ∈ {trusted, standard, low, blocked}. A `blocked` source's asserts are dropped in `Stream.admitted` before anything else; they are never confirmable and never counted. `core.py` `_ingest` returns early for blocked asserts but still appends them to `self.ingested`. **`blocked` is not exercised anywhere:** the generator's source table has only trusted/standard/low, and a grep of `tests/`, `scripts/` and the shipped streams finds no blocked source. So frozen-set agreement says nothing about blocked-source behaviour.

**Design.** `quarantined` source class: reports logged but not admitted until confirmed by an already-admissible report from another origin group. No `excluded` class is defined, although "admitted or rejected" and `excluded` appear as admission outcomes.

## Options

A. **Two distinct classes (recommended).** `blocked` ⇒ admission outcome `excluded` (permanent, never confirmable, reason recorded). `quarantined` ⇒ outcome `quarantined` until confirmed. Both are *source classes* declared per connector.
B. Treat `blocked` as an alias of `quarantined`. Loses the ability to say "never", which a poisoning response needs.
C. Drop `blocked` (paper-only concept); keep only quarantine.

## Recommendation

**A.** Add the missing outcome name to the admission contract: `admit() → {admissible | quarantined | excluded}`. Map the paper's `blocked` to `excluded` in the compat profile. Document that `excluded` reports remain in the log, queryable by audit, and never contribute to A-SELF (see S-02).

## Effect on `revise-stream-v1` and G1

The profile has no quarantined sources and maps `blocked → excluded`. Because no frozen stream uses `blocked`, G1 is vacuous for this behaviour; the fixtures below are the only guard, so they must be run through both the compat profile and the oracle (using a hand-built stream) to make the equivalence non-vacuous.

## Fixtures implied

- `fx-S03-blocked-never-admitted`: blocked source report never appears in provenance; `reported` slot omits it.
- `fx-S03-blocked-not-confirmable`: blocked report equivalent to a quarantined report does not confirm it.
- `fx-S03-quarantined-confirmed-by-third-origin`: as in the independent suite.
- `fx-S03-two-quarantined-no-mutual-confirmation`.
- `fx-S03-oracle-parity-blocked`: hand-built stream with a blocked source, compared with `oracle_v1`.

## Open questions

1. Can a source move between classes over time? If yes, reports admitted earlier keep their `admission_version`; later changes take effect only through a new admission version (recorded, auditable). Recommend yes.
2. Should reports from a source that is *later* quarantined be re-evaluated? Recommend: only via an explicit admission-version bump, never silently.

### Decision (author, 2026-10-04): **yes.** `excluded` carries a **reason code and the admission version**: exclusions are what an audit asks about first.

### Decision (author, 2026-10-05): a source going bad is an admission operation, `exclude_source` (ruling 2)

Source-scope `withdraw` is **not** added to the contract. The paper's `retract(source)` (which also removes the source's *later* assertions, the 85-query `late-assert` class that per-report withdraws cannot reach) is served in the product by an admission operation:

* `exclude_source(source, from_lsn, reason)` (host API, `palimem.admission`): from log position `from_lsn` on, the source's reports are not heard (they leave the kernel's evidence set), whether logged before the decision or after it. `restore_source(source, from_lsn, reason)` is a later recorded decision that lifts it for reports at or after `from_lsn`; for each report the last marker whose `from_lsn` is at most the report's position decides.
* **Recorded** as a marker report on the reserved attribute `__source_exclusion__` (the representation entity merges use): an assertion `{"op", "from_lsn", "reason"}` about the source, written by a `system:` or `user:` principal. It is in the hash-chained, idempotent, crash-safe log, carries its own admission record (reason `admitted` and the admission version in force) and is audit-visible with its reason text (`source_exclusions(mem)`). It is not a new cue and not a `Report` field. A marker from any other principal kind is logged but never honoured, and the host API refuses it.
* **Effect:** `ExclusionAdmitter` adds the excluded reports to the evaluation's withdrawal map with `Withdrawal(kind="source_exclusion", by=<marker id>)`, so the repair is the one every withdrawal triggers (revision of the touched keys and of everything derived from them), and an excluded report neither confirms a quarantined one nor corroborates. Reports stay in the log and keep their admission records. `belief_as_of` re-derives the exclusions in force at that position from the log prefix.
* **Reason code:** the excluded reports' admission *records* are unchanged (the exclusion is an effect, like a withdrawal, not a per-report outcome), so no new `AdmissionReason` value was added and the contract is untouched; the reason text lives in the marker. The compat profile's source retraction (`__source_status__`, the paper's behaviour) is a separate mechanism and unchanged.
* **Evidence:** `harness.exclusion_diff` replays all 500 frozen Setting 1 streams with the study's source retractions recorded as `exclude_source(from_lsn=1)` instead of the compat marker: **0 disagreements**, where the contract-expressible per-report expansion leaves the 85-query gap (`pipeline_diff --source-retract expand`). Its self-test (`--inject-bug forward-only`, excluding only from the decision on) fails the gate.
* **Limitation (documented, not fixed):** an excluded source's own operator actions on its own reports (a self-correction, a self-withdrawal) are moot, since those reports are not heard; its actions on other sources' reports are refused by the authority rules (default: own source only).
