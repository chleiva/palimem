# S-03 — Paper `blocked` versus design `quarantined`

Status: accepted* (2026-10-04) · Gate: G0 · Lane: A · Related: S-01, S-02, S-11

## Context

**Paper / code.** Source class ∈ {trusted, standard, low, blocked}. A `blocked` source's asserts are dropped in `Stream.admitted` before anything else; they are never confirmable and never counted. `core.py` `_ingest` returns early for blocked asserts but still appends them to `self.ingested`. **`blocked` is not exercised anywhere:** the generator's source table has only trusted/standard/low, and a grep of `tests/`, `scripts/` and the shipped streams finds no blocked source. So frozen-set agreement says nothing about blocked-source behaviour.

**Design.** `quarantined` source class: reports logged but not admitted until confirmed by an already-admissible report from another origin group. No `excluded` class is defined, although "admitted or rejected" and `excluded` appear as admission outcomes.

## Options

A. **Two distinct classes (recommended).** `blocked` ⇒ admission outcome `excluded` (permanent, never confirmable, reason recorded). `quarantined` ⇒ outcome `quarantined` until confirmed. Both are *source classes* declared per connector.
B. Treat `blocked` as an alias of `quarantined`. Loses the ability to say "never", which a poisoning response needs.
C. Drop `blocked` (paper-only concept); keep only quarantine.

## Recommendation

**A.** Add the missing outcome name to the admission contract: `admit() → {admissible | quarantined | excluded}`. Map the paper's `blocked` to `excluded` in the compat profile. Document that `excluded` reports remain in the log, queryable by audit, and never contribute to A-SELF (see S-02).

## Effect on `revise-stream-v1` and G1

The profile has no quarantined sources and maps `blocked → excluded`. Because no frozen stream uses `blocked`, G1 is vacuous for this behaviour; the fixtures below are the only guard, so they must be run through both the compat profile and the oracle (using a hand-built stream) to make the equivalence non-vacuous.

## Fixtures implied

- `fx-S03-blocked-never-admitted`: blocked source report never appears in provenance; `reported` slot omits it.
- `fx-S03-blocked-not-confirmable`: blocked report equivalent to a quarantined report does not confirm it.
- `fx-S03-quarantined-confirmed-by-third-origin`: as in the independent suite.
- `fx-S03-two-quarantined-no-mutual-confirmation`.
- `fx-S03-oracle-parity-blocked`: hand-built stream with a blocked source, compared with `oracle_v1`.

## Open questions

1. Can a source move between classes over time? If yes, reports admitted earlier keep their `admission_version`; later changes take effect only through a new admission version (recorded, auditable). Recommend yes.
2. Should reports from a source that is *later* quarantined be re-evaluated? Recommend: only via an explicit admission-version bump, never silently.
